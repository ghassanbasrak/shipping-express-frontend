# Ashamco Express migration conventions

Latest correction (2026-11-10): restore MediaInput and its existing variants to their original implementation. Do not reintroduce the upload-pipeline rewrite, controlled-value bridge, extracted upload/image-picker helpers, or changed failure/reset behavior. The only MediaInput extension is the `file` variant selecting a new FileInput: files like FileFieldInput, presented as an ImageInput-style box. Its selection/progress options stay in that variant. Wallet top-ups never persist or recover checkout from browser storage; opening a new top-up always resets to the online/bank-transfer form. Verify payment callbacks using their provider IDs and the existing backend contract. This correction supersedes conflicting media/recovery instructions below.

Payment/media policy (2026-11-10): customer-facing online payment labels use **Pay Online / الدفع الإلكتروني**, without gateway names in application copy. Preserve native Moyasar identifiers/contracts and provider-owned widget attribution. The provider supports hosted invoices but the current backend returns embedded form configuration only; do not invent hosted URLs or initiate secret-key invoice calls in the frontend. Hosted implementation requirements are in docs/wallet-funding-backend-handoff.md. All application file/image selection and uploads use shared-components/media-input/MediaInput, including controlled builder fields and rich-text image picking. Keep raw file controls and presigned uploads inside that component's internals; preserve cropping, MIME/size restrictions, upload busy locks and previous values after failed replacements.

Latest user policy (2026-11-10): fully retire packaging requests, including package-requests-app, packaging shortcuts, staff grants and demo catalog/request handlers. Keep warehouse/storage supply requests as a separate feature. Wallet top-ups offer native Moyasar online payment or merchant bank-transfer submission for staff review. Use POST v1/payments/moyasar with net amount only, returned payment/checkout config, and POST v1/payments/:paymentId/check-status with moyasarPaymentId only. No PayTabs/Hyperpay/MyFatoorah initiation/status writes remain active; old callback URLs redirect to server-read history. Bank POST v1/requests sends type=bankTransfer, gross amount and optional reference/receipt/notes; owner and pending status are server-assigned. Approval/rejection remain pending-only with existing bank-transfer view/update grants, and wallet credit is server-side. Preserve separate storage subscriptions and the shared callback router. Current UI enters gross total and shows net/VAT; final Moyasar checkout amounts are server-authoritative. See docs/wallet-funding-backend-handoff.md. This policy supersedes older packaging/payment instructions below.

Use `../bastaline-admin-frontend` as the reference for the new Fuse feature structure. Preserve existing Ashamco backend contracts and complete feature behavior. Reuse migrated shared components at their existing paths. Redux feature slices remain JavaScript (`*Slice.js`); pages, APIs, schemas, and entity models use TypeScript.

- An entity file such as `models/ICountry.ts` contains the root entity interface and exported interfaces for its nested domain objects (for example `IShipmentCountry`). Do not put form inputs, filters, pagination wrappers, request/response types, or unrelated entity interfaces there.
- Import reference entities from their own features. Pair reference IDs with populated fields: `countryId?: string; country?: ICountry;` and plural IDs with `countries?: ICountry[]`. Follow the backend's actual ID type. Migrate dependency entities/features before their consumers; ensure imports resolve. Do not claim a dependency feature is migrated when only its entity model exists.
- Keep `*Model.ts` focused on defaults and editable fields, following the reference. Put shared feature helpers in `Utils.ts`.
- Reuse validation helpers from `src/app/main/utils/validations.ts`. Use custom refinements such as `superRefine` for business rules. Preserve the source feature's required and optional fields.
- Follow reference `*Api.ts` structure: simple RTK Query endpoint definitions, request/response types declared in that file, and exported hooks. Avoid response normalization, generic PageResponse wrappers, transformResponse pipelines, and multi-request queryFn workflows. Keep any necessary multi-resource save orchestration in the feature's UI handlers and preserve recovery from partial saves.
- Follow reference detail pages: form methods and FormProvider in `Country.tsx`, a separate header, Tabs, and `country/tabs/BasicInfoTab.tsx`. Do not introduce a nested CountryForm component. Match reference FusePageCarded layout and header structure.
- Keep list pages such as `Countries.tsx` as simple FusePageCarded wrappers around their header and table. Put list initialization, filter selectors, queries, and pagination in the table as in the reference.
- Feature page headers use the approved shared `shared-components/feature-header/FeatureHeader.tsx` design: `p-16` at every breakpoint, organized title/context and action groups, and a compact full-width search/filter toolbar with equal visible end and vertical padding. Prefer Tailwind for layout, sizing, typography and responsive styling; reserve `sx` for theme-dependent colors. Keep detail back navigation as Typography links with direction-aware arrows, and retain each feature's local permission checks, handlers and query scopes. Printed report headings and authentication/payment callback layouts keep their specialized formats.
- Buttons inside MUI `Alert` components retain their original styles, including text-button defaults where applicable. They are exempt from the contained/outlined button rule; shared header action styling must not override nested Alert buttons.
- Specify matching `flex` and `minWidth` for every table column, with `minWidth = flex * 100`. Boolean/tiny columns: 0.3/30. Codes, dates, numbers, statuses, enums: 0.5-0.7/50-70. Phone/email: 0.8-0.9/80-90. Names, notes, actions: 0.9-1.3/90-130.
- Define feature enum constants in `Utils.ts`, for example `transactionStatus = { pending: "pending", completed: "completed" }`. Export matching title and color helpers (`toTransactionStatusTitle`, `toTransactionStatusColor`) and reuse them throughout the feature. Follow the reference's translation keys and color conventions. Do not invent enums where none exist.
- Preserve unsaved form edits during background refetches and retain returned backend IDs so subsequent mapping saves update the same record.
- Salla, Odoo, product e-commerce, and comparison features have been removed. Packaging requests are retired.

Validate affected behavior and run the active application typecheck/build. Full-source checks may include pre-existing unused template/shared-component issues; report their scope accurately.
